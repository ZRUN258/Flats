# Flats 半球面平整度检测系统

Flats 用于检测半球或球冠类样品（例如隐形眼镜）的表面平整度。系统由 Web 上位机和 Arduino Mega 2560
下位机组成：上位机生成检测路线、调度扫描、采集并可视化数据；下位机控制方位角、倾斜角和探头半径三个步进轴。

> 当前硬件仍在设计阶段，引脚、运动方向、单步对应角度/长度和机械限位均为占位配置。接入实机前必须完成标定。

## 系统架构

```text
┌────────────────────── Web 上位机（Chrome / Edge）──────────────────────┐
│ 路线生成 · 扫描状态机 · 三维球冠视图 · 数据记录 · CSV/PDF 导出          │
└──────────────────┬────────────────────────┬───────────────────────────┘
                   │ Web Serial 115200       │ Web Serial 115200（可选）
                   ▼                        ▼
       ┌──────────────────────┐   ┌─────────────────────┐
       │ Arduino Mega 2560    │   │ 外部传感器/采集设备 │
       │ AZ/TILT/R 三轴运动   │   │ 一次读数输出一行    │
       └──────────────────────┘   └─────────────────────┘
```

默认保持双串口设计：运动板和传感器分别连接上位机。也可以启用下位机模拟量传感器，通过运动串口的
`MEASURE` 命令完成采集。

## 快速开始

### 下位机

```bash
cd client
pio run
pio run -t upload
```

LazyVim/clangd 用户在依赖或开发板配置变化后运行 `pio run -t compiledb`。

### 上位机

Web Serial 需要安全上下文，不能直接双击 HTML：

```bash
cd host
python3 -m http.server 8080
```

使用最新版 Chrome 或 Edge 打开 [http://localhost:8080](http://localhost:8080)。Safari 和 Firefox 当前不支持
Web Serial。连接时浏览器会要求用户选择串口，网页不能绕过此授权步骤。

## 坐标与单位约定

| 轴 | 协议名称 | 含义 | 工程单位 | 当前占位精度 |
|---|---|---|---|---|
| 0 | `AZ` | 球坐标方位角 | 度（°） | 0.01°/步 |
| 1 | `TILT` | 从球冠顶点/极轴向外的倾斜角 | 度（°） | 0.01°/步 |
| 2 | `R` | 探头在球坐标径向的位置/距离 | 毫米（mm） | 0.001 mm/步 |

- 下位机内部位置始终使用有符号整数步数，单位坐标只在通讯边界换算。
- `目标步数 = round(目标单位值 / unitsPerStep)`。
- `positiveUsesCw` 只改变实际输出引脚，不改变协议坐标的正方向。
- 上电后没有绝对位置记忆或自动归零。完成原点开关前，需人工放到已知位置后执行 `ZERO`。

## 串口通讯协议

### 物理层与帧边界

| 参数 | 值 |
|---|---|
| 波特率 | 115200 baud |
| 数据格式 | 8 数据位、无校验、1 停止位（8N1） |
| 流控 | 无 |
| 编码 | ASCII |
| 字段分隔符 | 英文逗号 `,` |
| 普通帧结束符 | LF（`\n`）；接收端忽略 CR，兼容 `\r\n` |
| 最大帧长 | 95 字节，不含换行符 |
| 字母大小写 | 普通命令不敏感；建议统一使用大写 |

普通帧格式为 `COMMAND[,FIELD...]\n`。数值不得包含单位。浮点字段允许普通小数和科学计数法；步数字段
必须为十进制整数。运动期间下位机仍持续收包，因此可以查询位置或发送停止命令。

### 上位机 → 下位机命令帧

| 命令 | 帧格式 | 说明 | 典型响应 |
|---|---|---|---|
| 握手 | `PING\n` | 检查通讯 | `PONG` |
| 单位坐标绝对移动 | `MOVE,<az>,<tilt>,<r>\n` | 角度为度，半径为 mm | `ACK,MOVE`，到位后 `DONE,...` |
| 同义移动 | `GOTO,<az>,<tilt>,<r>\n` | 等价于 `MOVE` | 同上 |
| 步数绝对移动 | `MOVE_STEPS,<sa>,<st>,<sr>\n` | 三轴绝对步数 | `ACK,MOVE` |
| 相对点动 | `JOG,<axis>,<delta_steps>\n` | `axis` 为 `AZ`、`TILT` 或 `R` | `ACK,MOVE` |
| 查询位置 | `POS?\n` | 查询状态和实际位置 | `POS,IDLE,...` 或 `POS,MOVING,...` |
| 查询状态 | `STATUS?\n` | 当前等价于 `POS?` | 同上 |
| 平滑停止 | `STOP\n` | 按设定加速度减速，不是硬件急停 | `ACK,STOPPING`，停稳后 `DONE,...` |
| 设置软件零点 | `ZERO\n` | 仅允许静止时使用 | `ACK,ZERO` |
| 同义置零 | `SET_ZERO\n` | 等价于 `ZERO` | `ACK,ZERO` |
| 触发检测 | `MEASURE\n` | 仅板载传感器启用且机构静止时有效 | `DATA,<value>` |

轴名称兼容缩写及索引：`AZ/A/0`、`TILT/T/1`、`R/RADIUS/2`。

示例：

```text
MOVE,30.5000,20.0000,8.250
JOG,AZ,-1
MOVE_STEPS,3050,2000,8250
```

### 下位机 → 上位机响应帧

所有响应以 `\n` 结尾。

| 响应 | 帧格式 | 含义 |
|---|---|---|
| 启动就绪 | `READY,FLATS_SPHERICAL,2` | 固件通讯协议版本为 2 |
| 空闲位置 | `POS,IDLE,<az>,<tilt>,<r>,STEPS,<sa>,<st>,<sr>` | 当前静止位置 |
| 运动位置 | `POS,MOVING,<az>,<tilt>,<r>,STEPS,<sa>,<st>,<sr>` | 当前运动位置 |
| 接受运动 | `ACK,MOVE` | 目标有效并进入运动状态 |
| 已在目标 | `ACK,AT_TARGET` | 目标与当前位置相同，不产生 `DONE` |
| 开始停止 | `ACK,STOPPING` | 已进入减速停止过程 |
| 置零成功 | `ACK,ZERO` | 三轴当前位置和目标位置均设为 0 |
| 运动完成 | `DONE,<az>,<tilt>,<r>,STEPS,<sa>,<st>,<sr>` | 三轴到达目标或平滑停稳 |
| 检测数据 | `DATA,<value>` | 板载传感器读数 |
| 心跳响应 | `PONG` | `PING` 的响应 |
| 错误 | `ERR,<code>` | 命令未执行 |

位置字段定义：`az` 和 `tilt` 单位为度，分别输出 4 位小数；`r` 单位为 mm，输出 3 位小数；`sa/st/sr`
分别为三个轴的有符号整数步数。

完整通讯示例：

```text
HOST  > MOVE,30.5,20,8.25\n
BOARD < ACK,MOVE\n
BOARD < DONE,30.5000,20.0000,8.250,STEPS,3050,2000,8250\n
```

### 错误码

| 错误码 | 原因 | 建议处理 |
|---|---|---|
| `LINE_TOO_LONG` | 帧超过 95 字节 | 丢弃整帧并检查发送端 |
| `UNKNOWN_CMD` | 命令名称不存在 | 检查协议版本和拼写 |
| `MOVE_FORMAT` | `MOVE/GOTO` 字段非法 | 修正为三个有限数值 |
| `STEPS_FORMAT` | `MOVE_STEPS` 字段非法 | 修正为三个整数 |
| `JOG_FORMAT` | 轴名或相对步数非法 | 检查轴名称和整数步数 |
| `LIMIT` | 目标超出软件限位 | 修正路线，不要重试相同目标 |
| `BUSY` | 当前动作要求机构静止 | 等待 `DONE` 后重试 |
| `SENSOR_EXTERNAL` | 板载传感器未启用 | 使用外部串口或修改配置 |
| `SENSOR_READ` | 板载传感器采集失败 | 检查传感器模块 |
| `LEGACY_CMD` | 旧版两字节命令非法 | 改用正式 ASCII 帧 |

### 旧版两字节兼容帧

为兼容原 Python 上位机，下位机仍接受不带换行符的 `a1`～`f7`：

| 首字节 | 轴与方向 |
|---|---|
| `a` / `b` | AZ 正向 / 负向 |
| `c` / `d` | TILT 正向 / 负向 |
| `e` / `f` | R 正向 / 负向 |

第二字节 `1`～`7` 分别对应 `1、2、5、10、20、50、100` 步。新功能不要继续扩展旧格式，必须使用带
换行符的正式 ASCII 帧。

## 外部传感器通讯约定

每个运动点收到 `DONE` 后，上位机等待设定的稳定时间，再把外部传感器下一行中出现的第一个合法数值作为检测值。
以下内容均会解析为 `12.345`：

```text
12.345
VALUE,12.345
sensor: 12.345 um
```

建议传感器端统一输出 `DATA,<value>[,<unit>]\n`。传感器应做到“一次触发或一次稳定读数对应一行”。连续
高速输出可能使旧数据关联到新检测点；正式协议应增加采样序号、时间戳或显式触发/应答。

## 自动扫描时序

```text
生成/导入路线
  └─► 发送 MOVE
        └─► 收到 ACK,MOVE（仅表示已接受）
              └─► 等待 DONE
                    └─► 等待机械稳定时间
                          ├─► 外部串口下一行数据
                          ├─► MEASURE → DATA
                          └─► 手动录入/模拟
                                └─► 保存、绘图、统计 → 下一点
```

一次只能有一个等待关联的检测点。不要在 `DONE` 前发送 `MEASURE`，也不要把 `ACK,MOVE` 当成运动完成。

## 路线 CSV 格式

每行依次为方位角（度）、倾斜角（度）、球坐标半径（mm）：

```csv
azimuth_deg,tilt_deg,radius_mm
0,0,10
-45,15,10
45,15,10
```

解析器会忽略无法解析的表头和空行，因此可带或不带表头。球冠路线生成器根据样品曲率半径和有效口径计算最大
倾角；路线算法属于可替换模块，后续可升级为严格等面积、测地线或误差自适应采样。

## 下位机配置与标定

硬件参数集中在 `client/include/machine_config.h`：

| 配置 | 说明 |
|---|---|
| `cwPin` / `ccwPin` | 双脉冲驱动器方向脉冲引脚 |
| `unitsPerStep` | 每个整步对应的角度或长度 |
| `positiveUsesCw` | 协议正方向是否使用 CW 引脚 |
| `maxSpeed` | 最大速度，步/秒 |
| `acceleration` | 加速度，步/秒² |
| `STEP_PULSE_US` | 脉冲高电平宽度 |
| `LIMITS_ENABLED` | 是否启用软件限位 |
| `MIN_POSITION` / `MAX_POSITION` | 三轴工程单位限位 |
| `ONBOARD_SENSOR_ENABLED` | 是否启用 A0 模拟量采集 |

推荐标定顺序：

1. 脱离机械负载，用 `JOG,<axis>,1` 确认单步输出。
2. 确认正方向；反向时修改对应轴的 `positiveUsesCw`。
3. 测量固定步数产生的实际角度/长度，计算并填写 `unitsPerStep`。
4. 低速验证全行程，再设置最大速度和加速度。
5. 建立可靠原点后确定软件限位，最后启用 `LIMITS_ENABLED`。
6. 重复定位测试，确认回差、丢步和机构耦合误差。

## 多人开发约定

- **机构开发**：只通过 `Mechanism` 公共接口控制运动，不在指令模块中直接操作引脚或 `AccelStepper`。
- **协议开发**：新增命令集中修改 `command_processor.*`，同步更新本文档和上位机解析器。
- **传感器开发**：在 `Sensor` 中实现采集状态机，避免在 `loop()` 中长时间阻塞。
- **上位机开发**：运动帧解析集中在 `handleMotionLine`，传感器解析集中在 `handleSensorLine`。
- 新帧必须以换行结尾；响应必须明确区分“接受”“完成”和“错误”。
- 不依赖浮点坐标判断到位，以整数步数和 `DONE` 帧为准。
- `loop()`、串口读取和电机 `run()` 必须保持高频非阻塞调用。
- 修改通讯协议时递增 `READY,FLATS_SPHERICAL,<version>` 版本号。

提交前至少执行：

```bash
cd client
pio run
node --check ../host/app.js
```

## 已知限制与安全说明

- 当前没有硬件急停、原点开关处理、硬限位输入和掉电位置恢复。
- `STOP` 是软件减速停止，程序失控、USB 断连或驱动器故障时不能保证安全。
- 软件限位默认关闭，首次上机必须低速、低电流并准备独立硬件急停。
- 三轴由独立 `AccelStepper` 实例运行，不保证严格同时到达；当前只保证最终单步位置准确。
- 页面刷新会清空尚未导出的检测记录。

## 后续建议

1. 增加原点开关、硬限位和硬件急停链路。
2. 为命令和响应增加序号，避免异步帧关联歧义。
3. 为量产协议增加校验和或 CRC，并明确超时与重试规则。
4. 传感器协议增加采样序号、单位和质量状态。
5. 增加 EEPROM 标定参数、版本迁移和配置读写命令。
6. 增加基于串口模拟器的协议自动化测试。
